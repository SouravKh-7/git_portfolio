Machine Maintenance and Uptime Data Pipeline

A small Python pipeline for checking machine, sensor and maintenance data, then creating condition, reliability and maintenance-priority outputs.

Repository ↗Current evidencePortfolio home
01 · Problem

What problem am I solving?

Machine details, sensor readings and maintenance records often use different identifiers or contain bad rows. The pipeline uses one stable machine ID and keeps rejected records visible.

02 · Current state

What did I build?

A local Python and CSV flow validates three synthetic sources, keeps invalid rows in quarantine, calculates condition, health and reliability values, and produces a combined machine summary and maintenance-priority file.

Not built yet: Databricks, CDC, SCD Type 2, automated tests, production monitoring and ML.

03 · Architecture

Current local flow

  1. Synthetic sources
  2. Validation
  3. Processed / quarantine
  4. Condition & reliability
  5. Machine summary & priority
04 · Data engineering design

Traceable batch transformations

Raw, processed, quarantined and Gold directories make the transformation boundary visible. Scripts run in a documented sequence with stable `asset_id` joins and explicit error reasons.

05 · Data model

Identity first

The model joins asset master, timestamped telemetry and maintenance work orders through a permanent `AST-<SEQUENCE>` identifier. Plant, production line and status remain attributes rather than parts of the key.

06 · Reliability and quality controls

Reject visibly; qualify every metric

  • Invalid identifiers, references, codes, dates and numeric values are quarantined with reasons.
  • Latest telemetry drives condition; rule-based inputs drive health.
  • Availability uses a simplifying 30-day sample window and is not a production SLA.
07 · Evidence

Files that exist now

  • Python scripts for validation, processing and calculations.
  • Five valid synthetic machines and deliberately invalid sample rows.
  • Generated condition, health, reliability, combined-summary and maintenance-priority CSV files.
08 · Failure scenarios

Current and next failure coverage

The sample demonstrates malformed asset, telemetry and maintenance records. Duplicate arrival, replay, late data, partial failure, backfill and schema evolution remain future test scenarios.

09 · Business relevance

One machine view for maintenance review

The project makes condition, downtime and maintenance history easier to inspect. It does not claim measured downtime reduction or a live deployment.

10 · Current limitations

Early local MVP

Small synthetic data, file-based single-machine execution, no automated tests, no orchestrator, database, API, catalog, lineage, authentication, dashboard or production observability.
