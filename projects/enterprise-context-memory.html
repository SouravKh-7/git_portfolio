Future research / implementation direction

Enterprise Context & Organizational Memory Lab

A small, testable reference platform for deciding what a company AI should retrieve, what it may remember, and what should remain outside model learning.

This page presents architecture, a synthetic case study, and planned experiments. It does not claim an employer deployment, real employee data, or measured outcomes.

Explore architectureRead the companion article
Core question

How can an organization learn from its work without turning every conversation into permanent model memory?

Research focus
  • Permission-aware retrieval
  • Context routing
  • Memory write governance
  • Conflict and expiry
  • AI workflow evaluation

01 · Public explanation

The right evidence, for the right person, at the right time, under the right authority.

The model supplies general language and reasoning capability. The surrounding platform decides which organizational information is relevant, permitted, current, and trustworthy enough to use.

General

General knowledge

No enterprise retrieval is required.

Enterprise

Approved company knowledge

Retrieve current policy, definitions, and documents after access checks.

Live enterprise

Current operational state

Use authorized business systems, telemetry, incidents, and timestamps.

Hybrid

General reasoning + company constraints

Combine technical knowledge with the organization’s definitions and architecture.

02 · Core architecture

Context is assembled. Organizational memory is earned.

  1. 01InteractionQuestion, user, channel, sensitivity
  2. 02Context routerGeneral, enterprise, live, hybrid, ambiguous
  3. 03AuthorizationPolicy before retrieval or tool use
  4. 04Context fabricDocuments, data, definitions, live state, tools
  5. 05Answer / actionEvidence, uncertainty, abstention
  6. 06Memory write gateCandidate, evidence, review, ownership
  7. 07Governed memoryVersion, scope, access, expiry, supersession
  8. 08Evaluation & costQuality, safety, task outcome, unit economics
A company-specific AI should not try to memorize the company; it should assemble permitted, current context when needed and convert only validated experience into reusable memory.

03 · Learning versus memory

Different information needs different storage and control.

LayerSimple meaningTypical storageChange model weights?
Current contextInformation needed for this task nowPrompt, context window, tool resultsNo
Enterprise retrievalDocuments, structured data, policies, metrics, metadataDatabases, lakehouse, search, graphNo
Session memoryEarlier state in this conversation or workflowSession storeNo
User memoryExplicit, useful, user-controlled work preferencesPermissioned user memory storeUsually no
Organizational memoryReviewed facts, decisions, procedures, lessons, and skillsGoverned knowledge / memory storeNo
Model adaptationDeliberate update when context, tools, and prompting are insufficientFine-tuned or adapted modelYes—only when justified

Employee-memory rule: remember approved work context and explicit preferences where useful; do not silently infer attitude, loyalty, performance, health, personality, or manager-visible behavioral scores.

04 · Synthetic case study

Line 3 productivity falls after maintenance.

An operator asks why Line 3 is running slower today and mentions a similar earlier event. The system needs live plant context, but the employee’s recollection remains a hypothesis until verified.

  1. 01

    Route the question

    Classify it as live enterprise because it names an internal line and asks about today.

  2. 02

    Check access

    Allow Line 3 operations and maintenance summaries; exclude unrelated HR, finance, and restricted plant records.

  3. 03

    Build current state

    Retrieve throughput, downtime, telemetry, work orders, quality, incidents, shift notes, and procedures with timestamps and provenance.

  4. 04

    Extract a candidate lesson

    A previous lubrication-and-vibration conversation becomes investigation evidence—not organizational truth.

  5. 05

    Verify and review

    Compare prior incidents, retain contradictory evidence, and ask a reliability engineer to approve a narrower lesson.

  6. 06

    Store governed memory

    Attach machine-family scope, source evidence, owner, access policy, validity, review date, and supersession history.

  7. 07

    Measure usefulness

    Compare investigation time, evidence quality, unsupported claims, recommendations, corrections, and cost with and without memory.

05 · Planned experiments

Evaluation must cover usefulness, permission, memory quality, and cost.

Routing

Context Router Benchmark

Classify general, enterprise, live, hybrid, sensitive, and ambiguous questions; record confidence and abstention.

Security

Permission-Aware Retrieval

Test whether relevant-but-forbidden context is excluded before it reaches the model.

Memory

Memory Compiler

Measure candidate-memory precision and reviewer approval, correction, rejection, and conflict rates.

Lifecycle

TTL & Supersession

Expire or revalidate lessons based on age, use, contradictions, policy versions, and outcomes.

User control

Employee-Controlled Memory

Let users inspect, correct, delete, or disable assistance memory without exposing shared organizational data.

Economics

AI FinOps

Track cost per assist, investigation, resolved case, and approved action—not only tokens.
