02 / A closer look

Follow one result back to the code.

I started with three CSV files: machine master data, sensor readings and maintenance work orders. The pipeline checks the records, keeps invalid rows with a reason, and joins valid data through asset_id.

For one sample motor, the priority calculation is 30 + 20 + 15 + 20 = 85: health, criticality, failure history and downtime. A score of 60 or more is marked high priority.

Read the priority calculation ↗

    Read the source CSVs

  2. 02

    Check IDs, dates, codes and numeric values. Keep rejection reasons.

  3. 03
    Calculate and join

    Condition, health, reliability and the combined machine summary.

  4. 04

The rules are hand-written and the sample is small. Automated tests, streaming and model evaluation are the next work. No reduction in downtime has been measured.

04 / Approach and practical value

Build the logic. Test the result.
Then ask whether it helps.

I start by understanding the problem. When I explain a project, I show the implementation first, then the decision it could support.

Implementation

Make the rules visible.

Define the keys and record types. Write the validation and calculations. Keep rejected rows and explain why they failed.

Verification

Test the awkward cases.

Missing IDs, duplicate events and late records can change the answer. I want repeatable tests for those cases before adding more tools.

Business question

Check the effect on the work.

A maintenance summary could help an engineer review equipment. To claim an improvement, I would need to measure review time or decision quality against the existing process.

For the planned AI work, the assistant should retrieve records and explain the evidence. The engineer reviews the suggested checks and decides what to do.
