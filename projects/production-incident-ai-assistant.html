Production Incident AI Assistant

A planned tool for collecting incident evidence and helping an engineer review what happened.

Repository ↗Current evidencePortfolio home
01 · Problem

What problem am I solving?

During an incident, the useful details are spread across many tools. Engineers first need one timeline of alerts, logs, metrics, deployments, pipeline failures and runbooks.

02 · Current state

What exists now?

A small Python package, incident and evidence dataclasses, a read-only adapter protocol, one contract test, CI setup and design notes.

Not built yet: ingestion, correlation, retrieval, assistant, API, production integration and model evaluation.

03 · Architecture

Read-only evidence path

  1. Telemetry sources
  2. Read-only adapters
  3. Normalized evidence
  4. Correlation & retrieval
  5. Engineer review
04 · Data engineering design

Normalize before interpreting

The planned foundation separates collection, normalization, deterministic timelines, correlation, retrieval, permissioned tools and assistant output. Each derived statement must remain traceable to evidence identifiers.

05 · Data model

Incident, evidence and reference

Initial contracts preserve incident association, evidence type, source system, event time, ingestion time, source URI and source attributes. Assistant citations use stable evidence references.

06 · Reliability and quality controls

Evidence and authority boundaries

  • Read-only tools and least-privilege source access.
  • Provenance, timestamp and incident-boundary validation.
  • Hypotheses labeled separately from confirmed evidence.
  • No remediation tool or self-approved action in the initial build.

08 · Failure scenarios

Planned synthetic evaluations

Bad deployment, schema drift, late and duplicate data, telemetry loss, clock skew, alert noise, stale runbooks, permission denial and misleading historical similarity. No scenario result is claimed yet.

09 · Business relevance

Faster evidence assembly, with the engineer accountable

The intended value is a more coherent investigation record and better questions. No MTTR reduction, accuracy improvement or production outcome is claimed.
